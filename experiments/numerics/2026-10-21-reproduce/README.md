## Методические проблемы

1. **Точность в `k4_perp.py` (DPS=90 по умолчанию) недостаточна при r ≤ 1e-24.** U ∼ r⁹, q = x²+y²−z² даёт потерю
   теряются знаки из-за σ ≪ s (σ ∼ s^{5/4}), и шаги разностей очень малы: r·10^{−(24+0.8\|log₁₀ r\|)} (потребная точность оценена лишь эмпирически, по стабильности результата при росте DPS). При DPS=90, r=1e-24 получаем
   λ = −0.22 вместо 0.082; при r=1e-48 — мусор порядка 10³⁷. При DPS ≥ 250 (r=1e-24, 1e-48) и 300–700 (r до 1e-128)
   результаты стабильны (DPS 200/350/600 для r=1e-24 дают одинаковые −4.7008; 300 и 600 для r=1e-48 одинаковые −995.6).
   В заметках DPS не указан. Для `thmC_k4_K.py` (dps=80) проверено: dps=250 даёт те же −1.55201 и −0.283364.
2. **Размер прицельной выборки (NS) не указан, а результат от него критически зависит** (строки 4–5 таблицы
   k4_perp: при NS=100 худшая λ_min = +0.99978, при NS=400 −995.6). Метод «случайная прицельная выборка + min»
   лишь ищет контрпримеры; отсутствие отрицательных значений при 100 точках ничего не говорит о
   положительности в тонких областях.
3. **`probe.py`:** на тонких рогах выборка пуста: из 4000 случайных точек в шаре r=1e-3 в {U<0} попадает 3 (y²−x⁴)
   и 0 ((y−x²)²−x⁵); 1 из 4000 при r=0.01. Поэтому «inf» и «−0.0» в выводе — отсутствие данных, а не положительность.
   Заключение «λ_min до −50» опирается на r=0.1, где рог ещё толстый.
4. **`isolated_check.py`:** отношение min\|∇U\|/r⁵ растёт при уменьшении r (0.19 → 2.0) только из-за выборки: полоса,
   где \|∇U\| ∼ r⁵, имеет относительную ширину ∼ r² и 400 000 точек в неё не попадают при малых r. Целевая сетка по полосе
   (`example13/targeted_gradient_check.py`, φ×t = 4000×801, ρ = z + t·r³) даёт min\|∇U\|/r⁵ = 0.1869 при **всех**
   r = 0.1 … 0.001 (минимум в φ ≈ 3.619, t = 0, внутри окна), то есть ограниченность снизу в этом смысле подтверждается, а
   рост 0.19→2.0 — артефакт.
5. **Траектории (`example13/trajectories*.py`, `sieve/dyncheck*.py`) считаются РК4, не симплектической схемой.**
   Дрейф энергии относительно \|h\|: example13 при r₀=0.02: 17 %, при 0.01: 3000 % (грубый шаг); S3 в sieve при грубом шаге: 430 %.
   Надёжны только прогоны с мелким шагом (≤ 3 %). Время счёта траекторий ограничено, выход — сфера 0.3 (конечное время).
6. **Шаги конечных разностей:** в `thmB_example.py`, `thmC_*`, `k4_perp.py` шаги заданы относительно тонких масштабов
   (s·10⁻²⁰, s^{3/2}·10⁻²⁰, σ-шаг s^{5/4}·10⁻²⁵ и т. п.) и заведомо меньше ширины рога; проблем в этом отношении не найдено.
   В `numeric_check.py` (example13) шаг 1e-7·r; ширина рога по d оценивается из Q² = 4s²d² ≲ r⁶, то есть d ≲ r² (оценка моя), так что
   шаг меньше ширины при r ≫ 1e-7; для проверенных r ≥ 0.005 проблем нет.
7. **Выборки:** в `thmB_example.py` по 60 точек на масштаб, θ равномерна, поэтому нулей g(θ) выборка не
   разрешает; мой прицельный тест (`thmB_targeted.py`) положительность подтвердил. В `thm3_gradient.py` и `probe.py` выборки равномерные в шаре.
8. **`sieve`:** вердикты `[N13]` и `[N13*]` опираются на вириальный аргумент из `example13-proof.md`, который сам не проверен
   (в README это указано). Проверки изолированности и знаков в `sieve.py` — эвристические.

- Сито — сортировка по реализованным критериям с эвристическими проверками; «выжившие» не обязательно подозрительны.
